# AJERO 웹에이전시 홈페이지 PRD

## 1. 프로젝트 개요

### 프로젝트명

AJERO

### 프로젝트 목적

AJERO의 공식 웹사이트를 제작한다.

초기 웹에이전시로 포트폴리오가 많지 않은 상황에서도 단순히 제작 실적을 나열하는 것이 아니라,

* 전문성
* 신뢰성
* 체계적인 업무 방식
* 고객의 사업을 이해하는 능력
* 지속적인 유지보수 및 성장 지원

을 보여주어 잠재 고객이 상담 및 문의까지 자연스럽게 이어지도록 하는 것을 목표로 한다.

### 핵심 목표

> "홈페이지를 만들어주는 업체"가 아니라
> "고객의 사업을 웹으로 성장시키는 파트너"라는 인식을 만든다.

---

# 2. 타깃 고객

## 1차 타깃

* 인테리어 업체
* 건설/시공 업체
* 중소기업
* 홈페이지가 오래되어 리뉴얼이 필요한 기업
* 홈페이지는 있지만 관리가 제대로 되지 않는 기업
* 온라인 홍보 및 고객 유입을 강화하려는 사업자

## 고객의 주요 문제

* 오래된 홈페이지
* 모바일 대응 부족
* 홈페이지에서 회사의 전문성이 제대로 전달되지 않음
* 검색 노출 부족
* 블로그/광고/홈페이지가 서로 연결되지 않음
* 문의 및 예약 관리가 불편함
* 홈페이지 제작 후 관리해주는 업체가 없음
* 제작 업체와 연락이 잘 되지 않음

# 3. 홈페이지 핵심 전략

AJERO 홈페이지는 "우리가 얼마나 많은 프로젝트를 했는가"보다 다음을 강조한다.

### 핵심 메시지

1. 사업을 이해하고 만든다.
2. 디자인만 만드는 것이 아니라 실제 운영을 고려한다.
3. 홈페이지 제작 이후까지 관리한다.
4. 필요한 기능을 고객의 사업에 맞게 설계한다.
5. 작은 회사도 부담 없이 상담할 수 있다.

### 포트폴리오 부족 대응

포트폴리오를 억지로 많이 보여주지 않는다.

대신 다음 콘텐츠를 활용한다.

* 실제 제작 사례
* 자체 제작 데모 프로젝트
* 업종별 홈페이지 샘플
* 문제 → 해결 → 결과 형태의 Case Study
* AJERO의 제작 프로세스
* 서비스 구성
* 기술 및 운영 방식
* 유지보수 방식

실제 고객이 아닌 프로젝트는 반드시 "Concept Project" 또는 "Demo Project" 등으로 명확하게 구분한다.

가짜 고객사 및 허위 실적을 만들지 않는다.

# 6.6 Why AJERO

AJERO를 선택해야 하는 이유를 설명한다.

### 핵심 포인트

#### 01. 사업부터 이해합니다

웹사이트를 만들기 전에 고객의 사업과 고객 흐름을 먼저 이해한다.

#### 02. 필요한 것만 만듭니다

불필요한 기능을 넣기보다 실제 사업에 필요한 기능을 중심으로 설계한다.

#### 03. 제작 이후까지 생각합니다

홈페이지를 완성하는 것으로 끝내지 않고 유지보수와 지속적인 개선을 고려한다.

#### 04. 웹을 하나의 시스템으로 봅니다

홈페이지뿐 아니라 SEO, 콘텐츠, 예약, CRM, AI 등을 연결하여 운영할 수 있도록 설계한다.

# 6.7 Process Section

전문성과 신뢰성을 보여주기 위한 핵심 영역.

## 제작 프로세스

### 01. Consultation

고객의 사업과 현재 문제를 파악한다.

### 02. Planning

페이지 구조, 기능, 사용자 흐름을 설계한다.

### 03. Design

브랜드와 고객의 목적에 맞게 UI/UX를 설계한다.

### 04. Development

설계된 디자인을 실제 웹 서비스로 구현한다.

### 05. Launch

검수 후 실제 서비스를 배포한다.

### 06. Growth

유지보수, SEO, 콘텐츠, 기능 개선 등을 통해 지속적으로 관리한다.

프로세스는 단순한 숫자 나열보다 실제 업무가 어떻게 진행되는지 이해할 수 있도록 표현한다.

# 21. 개발 원칙

AI를 활용하여 개발하더라도 다음 원칙을 지킨다.

### 1. 컴포넌트 재사용

Button, Header, Footer, Section, Card 등의 공통 UI는 재사용한다.

### 2. 데이터와 UI 분리

Portfolio와 Blog 등의 콘텐츠 데이터를 UI 코드에 직접 하드코딩하지 않는다.

### 3. 디자인 토큰 사용

색상, 폰트, spacing, radius 등을 중앙에서 관리할 수 있도록 한다.

### 4. 페이지별 일관성 유지

페이지마다 완전히 다른 디자인을 만들지 않는다.

### 5. 과도한 기술 사용 금지

필요하지 않은 라이브러리와 복잡한 아키텍처를 사용하지 않는다.

### 6. 실제 고객에게 설명할 수 있는 수준으로 구현

AI가 생성한 기능이라도 개발자가 각 기능의 목적과 동작 방식을 이해할 수 있어야 한다.
